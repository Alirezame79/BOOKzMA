# ساختار پروژه

```
src/BOOKzMA/
  bot.py            ساخت ربات و dispatcher و شروع polling
  config.py         تنظیمات از env
  constants.py      ثابت‌ها: کانال‌ها، ساعت‌های آماده، منطقه‌های زمانی
  texts.py          همه متن‌های کاربر
  keyboards.py      کیبوردها
  utils.py          تبدیل عدد فارسی، پارس ساعت، منطقه زمانی
  handlers/         هر فیچر یه فایل (start, streak, reminders, timezone)
  middlewares/      session دیتابیس و چک عضویت کانال
  services/         منطق بدون وابستگی به تلگرام (streak) و حلقه یادآوری (scheduler)
  repositories/     کوئری‌های دیتابیس
  db/               مدل‌ها و ساخت session
migrations/         alembic
tests/              تست‌های منطق
```

## مسیر یه درخواست

پیام یا دکمه میاد، middleware اول عضویت کانال‌ها رو چک می‌کنه (پنج دقیقه کش می‌شه) و بعد یه session دیتابیس به هندلر می‌ده. هندلر از repositories داده می‌گیره، از services محاسبه می‌کنه، متن رو از texts و کیبورد رو از keyboards برمی‌داره و جواب می‌ده. commit رو خود هندلر می‌زنه.

## استریک چطور حساب می‌شه

عدد استریک ذخیره نمی‌شه. جدول `reading_logs` فقط تاریخ روزهایی رو نگه می‌داره که کاربر خونده و استریک هر بار از روی اون محاسبه می‌شه. «روز» به وقت منطقه زمانی کاربره. اگه دیروز خونده باشه و امروز هنوز نه، استریک زنده‌ست.

## یادآور

یه تسک پس‌زمینه (`services/scheduler.py`) هر ۳۰ ثانیه یادآورها رو می‌خونه. هر یادآور در روز یه بار فرستاده می‌شه، اگه کاربر همون روز خونده باشه فرستاده نمی‌شه، و اگه بیشتر از ۱۰ دقیقه دیر شده باشه (مثلاً ربات خاموش بوده) رد می‌شه.

## اضافه کردن یه فیچر جدید

1. اگه جدول لازمه: مدل توی `db/models.py` و یه migration
2. کوئری‌ها توی `repositories/`
3. منطق خالص توی `services/` با تست توی `tests/`
4. متن‌ها و کیبوردها توی `texts.py` و `keyboards.py`
5. یه فایل جدید توی `handlers/` و یه خط توی `handlers/__init__.py`

## چیزهایی که عمداً نداریم

Redis، webhook و پنل ادمین. تا وقتی نیاز واقعی نشده اضافه‌شون نمی‌کنیم. وضعیت مکالمه (برای افزودن ساعت دلخواه) توی حافظه نگه داشته می‌شه و با ری‌استارت ربات پاک می‌شه، که برای الان مشکلی نیست.
